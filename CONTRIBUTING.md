# Contributing

Carter Warrens repositories publish work at different maturity levels. Before proposing a change, review the repository README, implementation status, license, and open issues.

## Standard

- Keep claims proportional to verified behavior.
- Include tests or reproducible evidence for behavioral changes.
- Document assumptions, failure modes, and operational constraints.
- Never include credentials, client data, private research, or confidential material.
- Keep pull requests focused and explain the decision being made.

## Workflow

1. Open an issue for material changes so scope and ownership are clear.
2. Work on a focused branch.
3. Run the repository's documented checks.
4. Submit a pull request describing the change, evidence, risks, and rollback path.

Public contribution does not imply acceptance, endorsement, or a commercial relationship with Carter Warrens.
